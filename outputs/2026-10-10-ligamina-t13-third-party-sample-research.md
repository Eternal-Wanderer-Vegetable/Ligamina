# Ligamina T13 第三方插件候选调研

日期：2026-10-10。用途：为 T13/C11 样本锁定与后续 Runner 行为验收准备候选清单。**本报告只做来源和元数据调研，不代表任何候选已安装、加载、兼容或通过 L4。** 候选按 PyPI / npm Registry 在调研日返回的当前版本选定；精确包版本、分发制品 URL、Registry 声明的 hash、license 和上游地址分别连到 Registry/API 及项目源。

计划门槛是 20 个不同的真实插件包、每生态至少 10 个，覆盖消息/命令、任务、依赖与存储等场景；每生态至少 2 个 L4 通过且包含消息插件，必须在真实原生基准和联邦行为测试后才能认定。[执行计划 T13/C11](2026-10-09-ligamina-engineering-plan.md) · [MVP 清单 C11](2026-10-09-ligamina-mvp-checklist.md)

## 方法和边界

- 包身份、当前精确版本、PyPI wheel SHA-256、npm tarball SRI、`license` 及仓库 URL 以包索引的第一方记录为准：PyPI JSON API / npm Registry 精确版本元数据。每一行均附可直接打开的记录与制品链接。
- 行为/覆盖标签来自上游 README、项目说明或 Registry 描述；尚未下载源码进行 API 级审查，也未在 Ligamina Host 中运行。
- Python 候选选取 `py3-none-any` wheel；Node 候选选取 Registry `dist.tarball`，hash 保留其原生表示。报告未对下载字节独立重算，因此锁 manifest 生成时仍应下载制品并复核 hash。
- PyPI `license` 字段可能为空或是自由文本；npm 字段可能不是 SPDX 标准写法。此处记录上游/Registry 声明，不能替代法务复核。`nonebot-plugin-repeater` 的 PyPI license 为空，但 GitHub 显示 GPL-3.0；`nonebot-plugin-admin` 的 PyPI license 为空，暂标 `unknown`。
- 只把可安装为业务插件的包列为候选；不把 NoneBot/Koishi 框架、适配器或普通第三方依赖另算为插件。表中的 ORM、存储服务、AI 扩展自身都是可加载的插件包，但其依赖仍须在 lock 环境中单独锁定，不计入 20 个样本。
- 范围基线为计划的 NoneBot 2 + OneBot v11、Koishi 4 配置档和文本优先 MVP。依赖范围、外部服务、图片、管理操作或多 Bot 行为超出此档的，标为不适合当前 L4，或仅在裁剪场景后作为 L4 候选。

## L4 候选排序（均未通过）

后续最值得先做原生基准、再接联邦的纯消息场景：

1. NoneBot `nonebot-plugin-autohelp`：简单文本命令；还要确认当前框架加载、权限和 matcher 输出。
2. NoneBot `nonebot-plugin-repeater`：简单消息事件回显；需固定连续重复规则和群聊/私聊样例，且先审阅 GPL-3.0。
3. Koishi `koishi-plugin-multi-qa`：固定文本问答；只选纯文本 case，先验证配置存储、命令/消息匹配的原生语义。
4. Koishi `koishi-plugin-game-mini`：只启用猜数字，不启用需要 API key 的海龟汤；验证状态作用域和多轮消息序列。

这只是达到 L4 的可行性预判；C11 必须在两套独立环境完成原生行为基准、联邦运行、差分与故障证据后才能计为通过。当前计划支持 OneBot v11/Koishi 虚拟 Bot 的文本聊天配置档，不支持普通任意平台管理动作或图片二进制发送；见 [MVP C03–C05/C11](2026-10-09-ligamina-mvp-checklist.md)。

## manifest 候选字段建议

适配当前 Runner manifest：`sample_id` 用稳定短 slug；`ecosystem` 为 `nonebot` 或 `koishi`；`package`、`version`、`artifact_url`、`artifact_sha256`、`source_url`、`license`、`category` 直接取上表；缺失时用 `null` 或 `unknown` 并保留原因。NPM 的 `dist.integrity` 是 `sha512-...` SRI，并非 SHA-256；建议 manifest 允许 `artifact_hash_algorithm`，否则对 npm 锁文件先从 tarball 重算 SHA-256，并保留 Registry SRI 供交叉校验。`entry_module` / `entry_point` 不要仅凭包名猜：应从锁定制品的 `pyproject/package.json` 或源码确认后再写；上表已知的 PyPI import/module 名不能全部从发行名推导。
