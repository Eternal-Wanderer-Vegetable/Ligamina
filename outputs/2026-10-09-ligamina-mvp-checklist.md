# Ligamina v0.1 MVP 清单

日期：2026-10-09。状态更新于 2026-10-10：G1 技术闭环已通过；C01–C15 均是 G2 必选项，尚未完成最终验收，G2 保持 `NOT READY`。

关联文档：[初步计划](2026-10-09-ligamina-initial-plan.md)、[工程执行计划](2026-10-09-ligamina-engineering-plan.md)、[接口与证据](2026-10-09-ligamina-mvp-contracts.md)。本清单是首个可交付版本的范围；初步计划中的 AstrBot、Stella 集成和持续市场扫描在其后开展。

## 1. 一句话定义

**普通用户可以在 Windows 上启动 Ligamina，按需运行 NoneBot 和 Koishi 原生插件；独立客户端能够使用它们的命令与显式能力；每项兼容声明都可追溯到原生基准、联邦行为和故障测试。**

最小端到端路径：独立客户端 → Rust Core → 原生 Host → 受控平台操作 → 回执；同一组事件分别经过原生基准与联邦路径，生成可比较报告。

交付分两个检查点：G1 技术闭环证明方向可行；G2 MVP 交付同时满足下面所有必选项。G1 通过不标记 v0.1 发布就绪。

## 2. 必选清单

以下复选框只在对应 C 项达到 G2 证据门槛后勾选；G1 通过不代表 C01–C15 全部完成。当前所有 C 项仍待完整 G2 裁决。

- [ ] **C01 可复现工程。** Rust/Python/Node 工具链、框架、依赖锁文件和包哈希固定；Windows/Linux 有同一套公共契约检查。验收：干净检出可构建；修改包或 schema 时发现不一致。
- [ ] **C02 小而完整的 Core。** 管理宿主、路由、能力、授权、操作记录与错误；业务插件仅由 Host 加载。验收：使用公开客户端流程完成事件和能力调用；协议版本不匹配明确拒绝。
- [ ] **C03 两套原生 Host。** NoneBot 2 + OneBot v11 配置档，以及 Koishi 4 + Ligamina 虚拟 Bot。验收：既有插件业务文件哈希保持一致，原生规则、命令、依赖和生命周期入口实际执行；不支持的依赖/API 有具体原因。
- [ ] **C04 最小聊天配置档。** 私聊、群聊、文本、提及、回复引用；图片仅保留结构化引用。验收：发送者、账号、会话类型、回复关系与原始消息 ID 不丢失；同值群/私聊 ID 不混淆；未知必需消息段拒绝或标记该场景不支持。
- [ ] **C05 唯一输入和输出所有者。** 客户端提供平台网关，Host 经 Core 请求平台操作。验收：成功回复有平台回执；越权会话、账号及未授权操作被拒绝；插件不能通过桥接静默改变发送对象。
- [ ] **C06 明确事件路由。** 跨生态命令通过配置绑定到单一处理 Host，同生态由原生框架处理优先级。验收：冲突路由配置被拒绝或要求显式指定；不会默认广播给两个可回复 Host；原生阻断行为只声明在该 Host 内有效。
- [ ] **C07 能力调用与跨宿主服务。** 显式桥接至少一个纯函数能力/生态；MCP 客户端可发现、调用，桥接夹具可通过 Broker 调用另一 Host。验收：schema、授权、超时、错误和返回类型均验证；不把所有原生命令自动转为工具。
- [ ] **C08 可靠停止与重建。** 宿主按需启动，使用运行代次隔离旧实例；插件启用集合变化可重建该 Host。验收：初始化失败不发布能力；停用后旧代次输出拒绝；一个 Host 失败不影响另一个；Core 退出清理整个受管进程树。
- [ ] **C09 结果未知与重复请求处理。** 外部操作先落账，重复操作 ID 不重复发送；发送后断连保留 `unknown`。验收：相同 ID/相同载荷查询或复用结果，相同 ID/不同载荷报冲突；Core 重启后仍不自动重发未知操作。
- [ ] **C10 差分实验室。** 两个独立、同版本环境分别运行原生基准和联邦路径；虚拟平台记录事件、操作和回执。验收：先满足行为预期，再判断两边等价；刻意注入的错误能被检测。
- [ ] **C11 有范围的真实样本。** 至少 20 个唯一第三方插件，NoneBot/Koishi 各至少 10 个，依赖包不重复算作独立样本。验收：锁定版本和包哈希，覆盖命令、任务、依赖/存储等至少三类；每生态至少 2 个有 L4 行为通过证据，且包含消息插件；其他样本逐层给出真实状态。未通过者不写入支持名单。
- [ ] **C12 可检验的稳定性。** 两宿主各 100 次启停/重建，双宿主代表组合运行 24 小时并注入崩溃和断连。验收：零重复有效注册、零旧代次桥接输出、零退出后受管进程；资源曲线和恢复耗时达成固定预算。
- [ ] **C13 可复现报告与诊断。** JSON 为权威报告，生成 Markdown 摘要；CLI 提供状态和诊断。验收：每条结果有插件/框架/工具链版本、测试场景、深度、时间、失败原因和复现命令；`skipped/unknown` 不视为通过。
- [ ] **C14 Windows 个人交付。** 原生 Core + 可选 Python/Node runtime bundle，提供无需预装开发工具的安装流程。验收：干净 Windows x64 无 Python/Node/Docker 仍能运行选定插件；路径包含空格/中文可用；更新失败能恢复上个可用环境；卸载默认保留用户数据。
- [ ] **C15 Linux 单机契约验证。** 同一 Core/Host 版本可在 Linux x64 本机或单容器运行；提供单机 Compose 包装。验收：事件、能力、授权、崩溃恢复和结果未知场景与 Windows 一致；本版容器内部仍使用 stdio 子进程，Host 远程托管接口留到后续。

## 3. 首版明确支持的配置档

| 项目 | MVP 决定 | 说明 |
|---|---|---|
| Core | Rust，单实例，Tokio；SQLite 保存安装状态、运行代次及操作记录 | 私有实现由模块 Interface 封装 |
| NoneBot | 原生 NoneBot 2；OneBot v11 的群/私聊消息配置档 | 使用真实 Event/Bot 类型和原生预处理；不是支持所有 NoneBot 平台适配器 |
| Koishi | 原生 Koishi 4；自有虚拟 Bot/Adapter；选定本地存储支持 | 保留 Context、Session 和插件依赖逻辑；平台内部扩展接口按配置档支持 |
| Core ↔ Host | UTF-8 NDJSON，stdio 双向请求/响应，日志走 stderr | 协议与 MCP 分开版本化；Windows/Linux 共用 |
| 客户端接入 | 本机 HTTP 管理/事件/平台网关接口；MCP Streamable HTTP | 仅监听 loopback，绑定本地令牌；共用一个 Core |
| MCP | 首版声明 `2025-11-25`，Rust `rmcp` + 独立 TypeScript SDK 客户端验收 | `2026-07-28` 独立升级验证，不能用 SDK 默认值扩大支持声明 |
| 命令路由 | 每条事件一个显式处理 Host | 不模拟跨框架共享中间件或阻断链 |
| 授权主体 | 客户端和 Host 实例；操作受账号、会话和 grant 约束 | 同进程插件共享故障和权限域；插件 ID 是归属声明，不宣称恶意插件间强隔离 |
| 插件变更 | 更新启用集合后停止/重建对应 Host | 同 Host 的其他插件一起恢复；不承诺任意插件无损热替换 |
| 安装来源 | 批准的精确包/源码版本，依赖有锁定与哈希 | 首版使用本地清单导入和锁定环境，不依赖完整插件商店 |

图片引用可以进入事件并作差分比较；实际下载、转码、上传及二进制消息发送不属于首版支持声明。平台读取只实现最小的消息引用查询与账号信息查询，发送支持群/私聊；管理群成员等动作返回 `unsupported_api`。

普通子进程负责故障隔离。MVP 用户模式只运行用户信任的插件；批量第三方实验从安装阶段起使用一次性受限 Worker。桥接授权不限制插件直接访问操作系统的能力。

## 5. G1 和 G2 的裁决方式

**G1 技术闭环：** 两套宿主的自制原生插件分别收到群/私聊事件，经网关回复；独立 MCP 客户端调用两边能力；一个 Host 崩溃后能力撤销，另一边继续工作；差分 Runner 能识别故意注入的错误。C01–C10 可以先覆盖基本路径，C11–C15 的完整门槛仍待完成。

**G2 MVP 就绪：** C01–C15 全部有证据；契约场景零阻断缺陷；真实样本未支持的部分明确列出；干净 Windows 和 Linux 验收已执行。任一必选项缺证据时，裁决为 `NOT READY`。

20 个样本用于最低广度，不等于支持 20 个插件。支持名单只包含通过对应安装、加载、行为及必要稳定性测试的精确版本；功能支持范围随名单一起公布。
